# 05 — Packaging and Installation

## What a VPK is

A VPK is a **ZIP archive** used by the community. It is not a Sony package
format. Standard tooling puts these at the archive root:

```text
sce_sys/param.sfo
eboot.bin
sce_sys/icon0.png
sce_sys/livearea/contents/bg.png
sce_sys/livearea/contents/startup.png
sce_sys/livearea/contents/template.xml
```

`vita-pack-vpk` always adds `sce_sys/param.sfo` and `eboot.bin`; `-a src=dst`
adds assets. A VPK can also contain additional data files and plugins
(`.skprx`, `.suprx`).

## `param.sfo`

Generated by `vita-mksfoex` through `vita_create_vpk`. The 2026.08 defaults,
verified by parsing a generated SFO:

| Key | Type | Default / meaning |
|---|---|---|
| `APP_VER` | string | `00.00` (raw tool; `vita_create_vpk` sets it to `VITA_VERSION`) |
| `ATTRIBUTE` | dword | `0x8000` (`NO_COMMUNICATION_ZONE`) |
| `ATTRIBUTE2` | dword | `0`; `12` requests enlarged memory |
| `ATTRIBUTE_MINOR` | dword | `0x10` |
| `BOOT_FILE` | string | empty |
| `CATEGORY` | string | `gd` |
| `CONTENT_ID` | string | empty unless set; use `HB0001-<TID>_00-...` |
| `EBOOT_APP_MEMSIZE` | dword | `0` |
| `EBOOT_ATTRIBUTE` | dword | `0` |
| `EBOOT_PHY_MEMSIZE` | dword | `0` |
| `LAREA_TYPE` | dword | `0` |
| `NP_COMMUNICATION_ID` | string | empty |
| `PARENTAL_LEVEL` | dword | `0` |
| `PSP2_DISP_VER` | string | `00.000` |
| `PSP2_SYSTEM_VER` | dword | `0` |
| `STITLE` | string | title |
| `TITLE` | string | title |
| `TITLE_ID` | string | 9 chars |
| `VERSION` | string | `00.00` unless set |

Our projects set `VERSION` and `CONTENT_ID` explicitly.

## Title ID

- Exactly **9 characters**.
- VitaShell enforces **uppercase** (`strncmp(titleid, strupr(titleid), 9)`).
- Recommended `XXXXYYYYY`: 4-char author prefix + 5-char app number.
- Not necessarily "4 letters + 5 digits": `VITASHELL` is valid.
- Avoid Sony's `NPXS*` system namespace.
- Changing the title ID creates a new bubble and a new `ux0:app/<TID>` directory;
  old data does not follow.

Examples: `MLCL00001` (molecularShell), `VSDK00007` (sample), `VITASHELL`.

## Version

`VITA_VERSION` must match:

```text
^[0-9][0-9]\.[0-9][0-9]$
```

So `01.00` is valid; `1.0`, `1.00`, `02.0` fail with:

```text
Invalid version '1.0' change to format ##.##
```

## LiveArea assets

| File | Size | Notes |
|---|---|---|
| `sce_sys/icon0.png` | 128 × 128 | Bubble icon; opaque |
| `sce_sys/pic0.png` | 960 × 544 | Recommended; loading image |
| `sce_sys/livearea/contents/bg.png` | 840 × 500 | Background; name must match template |
| `sce_sys/livearea/contents/startup.png` | 280 × 158 | Startup image |
| `sce_sys/livearea/contents/template.xml` | — | Layout |

### Image format

- The installer validates PNGs. **Indexed/palette PNG (color type 3)** is the
  safe choice.
- 8-bit indexed is a safe default, but 1-bit indexed also works (the official
  `hello_world` `bg.png` is 1-bit).
- Non-indexed PNGs (color type 2/6) can fail install with `0x8010113D` at 99%.
- `pngquant` is a common conversion tool.
- `icon0.png` should be opaque; alpha is not wanted in the circular bubble.
- `pic0.png` is widely recommended; include it.

### `template.xml`

Minimal:

```xml
<?xml version="1.0" encoding="utf-8"?>
<livearea style="a1" format-ver="01.00" content-rev="1">
  <livearea-background>
    <image>bg.png</image>
  </livearea-background>

  <gate>
    <startup-image>startup.png</startup-image>
  </gate>
</livearea>
```

`style="a1"` centers the startup image. `style="psmobile"` supports frames,
text, images, and links. The background file name is whatever you put inside
`<image>`; `bg.png` and `bg0.png` are both valid conventions.

## Safe vs unsafe

| Build | CMake | Auth ID | Access |
|---|---|---|---|
| Safe | default | `0x2F00000000000002` | Restricted APIs/filesystem; runs without unsafe setting |
| Unsafe | `UNSAFE` | `0x2F00000000000001` | Full/private APIs; requires Enable Unsafe Homebrew |
| Secret-safe | `VITA_MAKE_FSELF_FLAGS=-ss` (manual) | `0x2F00000000000003` | Advanced; the installed 2026.08 CMake helper has no `SECRETSAFE` option |

Safe apps can use `ux0:data`, `app0:` (read-only), `savedata0:`, and normal app
APIs. They cannot freely browse `ux0:`/`ur0:` or use private system APIs.

**Start safe.** Add `UNSAFE` only when a specific API requires it. Shipping
unsafe unnecessarily makes users enable a system-wide security relaxation.

## How VitaShell installs a VPK

VitaShell does more than unzip:

1. Opens the VPK as an archive.
2. Extracts to `ux0:data/pkg`.
3. Reads `sce_sys/param.sfo`; gets `TITLE_ID` and `CONTENT_ID`.
4. Creates `sce_sys/package/head.bin` (fake package header with HMAC fields).
5. Calls `scePromoterUtilityPromotePkgWithRif("ux0:data/pkg", 1)`.
6. The system installs to `ux0:app/<TITLEID>` and registers the LiveArea bubble.
7. Deletes the temporary package directory.

This is why the VPK needs a real `param.sfo` and `eboot.bin`, not just a folder
of files.

### Folder install

VitaShell can also install a folder containing `sce_sys/param.sfo` and
`eboot.bin`: it renames the folder to the package directory and runs the same
promotion path.

### Manual copy + Refresh LiveArea

You can copy an app into `ux0:app/<TITLEID>` and use VitaShell's
**Refresh LiveArea**, but the promoter route is cleaner.

## Uploading

VitaShell FTP:

```sh
# On Vita: VitaShell -> Select -> note IP
curl -T build/app.vpk ftp://<VITA_IP>:1337/ux0:/data/
```

Then on the Vita:

1. VitaShell → `ux0:data`
2. Select the `.vpk`
3. Press **Cross**
4. Launch the bubble

USB transfer through VitaShell works too.

## Fast iteration

Reinstalling a VPK for every change is slow. Replace just the eboot:

```sh
curl -T build/eboot.bin ftp://<VITA_IP>:1337/ux0:/app/<TITLEID>/eboot.bin
```

Then relaunch the app. `eboot.bin` is a normal file in `ux0:app/<TID>`.

With `vitacompanion` (port 1338):

```sh
echo 'quit <TITLEID>'   | nc <VITA_IP> 1338
curl -T build/eboot.bin ftp://<VITA_IP>:1337/ux0:/app/<TITLEID>/eboot.bin
echo 'launch <TITLEID>' | nc <VITA_IP> 1338
```

## Install errors

| Symptom / code | Meaning | Fix |
|---|---|---|
| `0x8010113D` at 99% | Asset validation; usually non-indexed PNG | Re-encode `sce_sys` PNGs as indexed/palette |
| `0x80010005` | I/O error during install | Check free space, card, stale config; reboot |
| `0xFFFFFFFF` | Generic VitaShell/install failure | Inspect ZIP: `eboot.bin` + `sce_sys/param.sfo` at root |
| `C2-12828-1` | App crashed at launch | Check unsafe setting, dependencies; pull core dump |
| `C1-6775-5` | HENkaku/taiHEN not active | Re-run exploit or boot Enso |
| `C1-6703-6` | App requires higher firmware / compatibility plugin | Load `0syscall6`/`reF00D` under `*KERNEL` |
| `0x8002D011` | Required module not loaded (`MODULEMGR_NO_MOD`) | Reboot, reset taiHEN config, check storage driver |
| `0x8002D002` | Module in use; cannot unload | See kernel plugin unloading |
| Install fails while app runs | Old process holds app directory | Close app, retry |
| VPK > 4 GiB on FAT32 | FAT32 limit | Use exFAT or split content |
| Title ID already exists | Installer replaces existing app | Delete old app/bubble or use a new title ID |

## VPK size

- Small apps: tens of KB.
- `vita-kernel-demo`: 74 KB.
- `vita-cap-test`: 2.6 MB because it links SDL2, curl, mbedTLS, libarchive,
  libwebp, codecs, etc.
- Real apps should link only what they use.

## Packaging checklist

- [ ] `TITLE_ID` 9 uppercase chars, unique.
- [ ] `VITA_VERSION` `##.##`.
- [ ] `CONTENT_ID` set (`HB0001-...`).
- [ ] `eboot.bin` and `sce_sys/param.sfo` at VPK root.
- [ ] LiveArea PNGs indexed/palette.
- [ ] `template.xml` references the actual background/startup names.
- [ ] Safe build unless a specific API needs unsafe.
- [ ] Keep the unstripped ELF.
- [ ] Test install on a cold boot.
